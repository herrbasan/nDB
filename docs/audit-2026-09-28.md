# nDB Audit 2026-09-28 — consolidated report

> Three DeepSeek V4 Flash sweeps (code, docs, tests) over the v1.4.0 tree.
> Every finding below was **verified against source by the primary session** before
> being promoted to a work item. Raw subagent claims that did not survive
> verification are listed at the end as rejected.

## Verified blockers (data loss / crash / compat break)

### B1 — `ndb init` writes a `meta.json` the core refuses to open
- **Evidence:** [src/bin/ndb.rs](src/bin/ndb.rs#L180) writes `"buckets": {:?}` with a
  `Vec<String>` → an **array** (`[]` / `["a"]`). [load_bucket_policies](src/lib.rs) requires
  an object and fails `open()` with Corruption otherwise — my own phase10 malformed-shape
  test (`"buckets": ["avatars"]` → Corruption) proves the collision. Also written by
  `ndb merge` ([ndb.rs](src/bin/ndb.rs#L659)) and `ndb config set buckets a,b`.
- **Impact:** every CLI-created database fails `Database::open` since #10 landed.
  `ndb verify` step 3 silently degrades. Breaks the compatibility contract for existing
  CLI-created folders in the wild.
- **Fix:** CLI emits the object form (`"buckets": { "<name>": {} }`); loader accepts a
  legacy array as "names, no policy" (compat) instead of erroring. Regression test:
  init-shaped meta.json opens cleanly.

### B2 — `handle_patch` unwraps caller JSON; `panic = "abort"` kills the daemon
- **Evidence:** [src/server.rs](src/server.rs#L685) — `.ok_or_else(|| Error::invalid_arg(...)).unwrap()`
  on `path`/`value` for set/remove/array_push. Release profile is `panic = "abort"`.
  A malformed `PATCH /doc/{id}` aborts the server instead of returning 400.
- **Fix:** replace with `?`-style extraction returning `(400, json!({"error": ...}))`.
  Test: malformed PATCH ops → 400, server alive.

### B3 — trash-file rewrite races `delete()`'s trash append → unrestorable documents
- **Evidence:** `delete()` writes the restorable copy under `self.writer`
  ([lib.rs](src/lib.rs#L1567)), but `purge_trash` ([lib.rs](src/lib.rs#L1956)) and the
  TTL thread's `purge_trash_static` take **no** lock and do read-all → `rewrite_atomic`.
  Interleave: append lands after purge's read → purge rewrites the trash file without
  the new record → `restore()` returns NotFound for a just-deleted doc.
- **Fix:** a dedicated `trash_lock: Arc<Mutex<()>>` shared by `delete()`'s trash append,
  `purge_trash`, and the TTL thread (purge_trash_static takes it as a parameter).
  Test: injected interleave or at minimum a stress test hammering delete+purge.

## Verified bugs

### G1 — `restore()` violates journal-first ordering
[lib.rs](src/lib.rs#L2115): files restored and ref counters incremented **before** the
journal append; also no check that the doc is currently deleted (double-restore inflates
counters). Fix: append first, then files/counters; refuse when not deleted.

### G2 — `release_file` / `gc_buckets` take no writer lock
[lib.rs](src/lib.rs#L2348), [lib.rs](src/lib.rs#L2378): mark-and-sweep over `docs` with no
serialization against writers → a concurrent insert referencing a "dead" file gets it
trashed. Fix: take `self.writer.lock()` in both.

### G3 — TTL-thread reserved sweep races `commit_item`
My own #9 code: the thread calls `ItemBucket::sweep_reserved` directly, bypassing
`Database::writer`; selection (Reserved) and tombstone are not atomic with a commit.
Fix: `writer: Arc<Mutex<()>>`, the TTL thread takes it around the sweep.

### G4 — napi/CLI query paths skip `validate_query_ast`
`Database::query`/`query_with` ([lib.rs](src/lib.rs#L1748)) never validate; unknown
operators silently match everything (`_ => true`, [lib.rs](src/lib.rs#L389)). Only the
HTTP route validates. Fix: validate in `query`/`query_with` themselves.

### G5 — phrase `Exclude` over-excludes (full-text search)
[src/search.rs](src/search.rs#L481): excludes diff against token-conjunction candidates,
not verified phrases. Fix: verify phrase excludes against raw text before diffing.

### G6 — item `verify` can panic on a hand-corrupted journal
[src/item.rs](src/item.rs#L428): `expect("live item has facts")` — but `from_json` accepts
`state:"live"` with no facts. Fix: enforce live-requires-facts in `from_json`
(Corruption), no `expect` in verify.

## Risks (accepted for the work list, lower priority)

- R1 `Persistence::Scheduled` is a silent no-op ([lib.rs](src/lib.rs#L60) — stored, never
  read). Implement timed flush or reject loudly.
- R2 `set`/`remove`/`array_push` return Ok on unresolved paths (silent no-op) — decide:
  current behavior is documented and tested; tightening breaks replay leniency. **Defer
  with a decision needed.**
- R3 napi `restore_file` classifies errors by message substring
  ([napi/src/lib.rs](napi/src/lib.rs#L604)) — match on the Error variant instead.
- R4 doc journal tolerates malformed lines (silent skip; a corrupted tombstone resurrects
  a document) while the item journal fails loud — opposite policies, needs a deliberate
  decision and a doc note either way.
- R5 text-index `remove_doc` never reclaims dense ids (unbounded growth over many updates).

## Test gaps (verified highlights)

- **CLI is entirely untested** — no suite spawns `ndb.exe`. Round-trip test:
  init → dump → import; corrupt → verify exits 2; merge asserts union.
- **Failure injection missing on:** `insert` journal failure, `delete` tombstone-append
  failure, `compact` mid-rewrite failure (`data.jsonl.tmp` blocked), `export_snapshot`
  blocked target, item `commit`/`delete` journal failure, item `restore` with missing
  trash folder, sweep failure propagation, malformed `items.jsonl` at open.
- **Weak:** phase11 corruption case trips the *size* check — the streaming sha256 compare
  never executes (tamper same-length to assert "sha256 mismatch").
- **Concurrency:** the single-writer claim is never tested with actual concurrent writers.
- `release_file` has no test anywhere (Rust or napi).

## Rejected / not actionable after verification

  not a defect. Noted, no action.
- "`usize`→`u32` truncation" — 4 billion documents/files is outside design scope. Noted.
