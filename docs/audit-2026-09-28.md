## Verified blockers (data loss / crash / compat break)

### B1 — `ndb init` writes a `meta.json` the core refuses to open
- **Evidence:** [src/bin/ndb.rs](src/bin/ndb.rs#L180) writes `"buckets": {:?}` with a
  `Vec<String>` → an **array** (`[]` / `["a"]`). [load_bucket_policies](src/lib.rs) requires
  an object and fails `open()` with Corruption otherwise — my own phase10 malformed-shape
  test (`"buckets": ["avatars"]` → Corruption) proves the collision. Also written by
  `ndb merge` ([ndb.rs](src/bin/ndb.rs#L659)) and `ndb config set buckets a,b`.
- **Impact:** every CLI-created database fails `Database::open` since #10 landed.
  `ndb verify` step 3 silently degrades. Breaks the compatibility contract for existing
  CLI-created folders in the wild.
- **Fix:** CLI emits the object form (`"buckets": { "<name>": {} }`); loader accepts a
  legacy array as "names, no policy" (compat) instead of erroring. Regression test:
  init-shaped meta.json opens cleanly.
- **FIXED 2026-09-28:** all CLI writers (init/merge/recover/config set) emit object form;
  merge now reads BOTH metas in both forms (previously array-only — merging a
  library-shaped meta unioned zero buckets and dropped all policies), preserves policy
  blocks with base-wins semantics, and fails loud on unparseable merge-in meta (was
  silent skip); `config set` single-name case fixed (wrote a bare string); `config` no
  longer swallows corrupt meta.json into `{}`; `info` reads both forms. Loader accepts
  legacy name-arrays as no-policy, non-string entries stay Corruption. Tests: phase10
  compat + malformed `[1]`, new `tests/phase12_cli_tests.rs` spawns the real binary
  (init±buckets → open, config set → open, merge policy-preservation → open). 264 Rust
  + 72 napi green.

### B2 — `handle_patch` unwraps caller JSON; `panic = "abort"` kills the daemon
- **Evidence:** [src/server.rs](src/server.rs#L685) — `.ok_or_else(|| Error::invalid_arg(...)).unwrap()`
  on `path`/`value` for set/remove/array_push. Release profile is `panic = "abort"`.
  A malformed `PATCH /doc/{id}` aborts the server instead of returning 400.
- **Fix:** replace with `?`-style extraction returning `(400, json!({"error": ...}))`.
  Test: malformed PATCH ops → 400, server alive.

### B3 — trash-file rewrite races `delete()`'s trash append → unrestorable documents
- **Evidence:** `delete()` writes the restorable copy under `self.writer`
  ([lib.rs](src/lib.rs#L1567)), but `purge_trash` ([lib.rs](src/lib.rs#L1956)) and the
  TTL thread's `purge_trash_static` take **no** lock and do read-all → `rewrite_atomic`.
  Interleave: append lands after purge's read → purge rewrites the trash file without
  the new record → `restore()` returns NotFound for a just-deleted doc.
- **Fix:** a dedicated `trash_lock: Arc<Mutex<()>>` shared by `delete()`'s trash append,
  `purge_trash`, and the TTL thread (purge_trash_static takes it as a parameter).
  Test: injected interleave or at minimum a stress test hammering delete+purge.
- **FIXED 2026-09-28:** `trash_lock` added (always taken after `writer`; purge paths never
  take `writer` — no inversion). Hammer test `purge_during_deletes_never_loses_a_fresh_trash_record`
  (300 deletes × foreground purger × 5ms TTL thread, churn-seeded so every purge rewrites):
  verified it FAILS with the guards removed and passes 5/5 with them. Two hard-won test
  lessons: (1) a purge only rewrites when something expired — fresh-only trash never opens
  the race window, so the test seeds an expirable record per sweep; (2) the seed itself must
  append under the trash lock — `writeln!` is multi-syscall, an unsynchronized appender
  interleaves mid-line and corrupts a locked writer's line (line tearing, a different bug
  class — feeds D2). 266 Rust + 72 napi green.

## Verified bugs

### G1 — `restore()` violates journal-first ordering
[lib.rs](src/lib.rs#L2115): files restored and ref counters incremented **before** the
journal append; also no check that the doc is currently deleted (double-restore inflates
counters). Fix: append first, then files/counters; refuse when not deleted.
**FIXED 2026-09-28:** journal append now precedes file returns, counter bumps and
in-memory state (failed append = nothing moved, retryable — pinned by fault-injected
phase9 test using the break_journal/heal_journal probe); restore refuses a doc that is
not currently deleted (`InvalidArgument`) — the trash file keeps entries after a restore,
so a second restore used to re-inflate counters (pinned by lib test incl. counter sanity
via re-delete trashing the file again). 268 Rust + 72 napi green.

### G2 — `release_file` / `gc_buckets` take no writer lock
[lib.rs](src/lib.rs#L2348), [lib.rs](src/lib.rs#L2378): mark-and-sweep over `docs` with no
serialization against writers → a concurrent insert referencing a "dead" file gets it
trashed. Fix: take `self.writer.lock()` in both.
**FIXED 2026-09-28:** both take `writer` for their whole scan+sweep. Note on testability:
a black-box race reproduction is *impossible to make non-vacuous* — the mark phase holds
the docs read lock for its full scan (consistent snapshot), and the illegal interleave's
end-state is indistinguishable from the legal ordering (gc completes, then a doc references
an already-trashed file). The lock's guarantee is serializability, correct by construction.
Shipped instead: `gc_purge_and_writers_run_concurrently_without_corruption` — concurrent
gc + purge + insert/set/delete hammer proving the combined lock graph (writer, trash_lock)
neither deadlocks nor corrupts (anchored files never trashed; every live doc's refs
resolve). 269 Rust + 72 napi green, 3/3 stable.

### G3 — TTL-thread reserved sweep races `commit_item`
My own #9 code: the thread calls `ItemBucket::sweep_reserved` directly, bypassing
`Database::writer`; selection (Reserved) and tombstone are not atomic with a commit.
Fix: `writer: Arc<Mutex<()>>`, the TTL thread takes it around the sweep.
**FIXED 2026-09-28:** `writer` is now `Arc<Mutex<()>>` (all `self.writer.lock()` sites
unchanged via Deref); the TTL thread holds it around the reserved sweep — same
serialization as the public `sweep_reserved_items`. Test drives the REAL product thread
(`reserved_ttl_seconds: 0`, 25 ms interval) against a 200× create→commit hammer: every
Ok commit reads back live, verify clean, journal replays clean. Verified FAILS with the
thread lock removed (non-vacuous), 3/3 stable with it. 270 Rust + 72 napi green.

### G4 — napi/CLI query paths skip `validate_query_ast`
`Database::query`/`query_with` ([lib.rs](src/lib.rs#L1748)) never validate; unknown
operators silently match everything (`_ => true`, [lib.rs](src/lib.rs#L389)). Only the
HTTP route validates. Fix: validate in `query`/`query_with` themselves.
**FIXED 2026-09-28:** `query`/`query_with`/`query_projected` validate first and return
`Result` (`Err(InvalidArgument)` on unknown operators/malformed combinators/non-object
roots — every path: library, napi, HTTP; the HTTP pre-validation stays as the 400-shaper,
the core Result is the second net). ⚠️ **Breaking API change**: Rust `query -> Result<Vec<Value>>`
(and `query_with`/`query_projected`); JS `query`/`queryWith` reject on invalid ASTs —
flag in release notes. Consumers verified: Arena Slides uses `query({})` (valid); nGDB
passes LLM ASTs through — typos now surface as correctable tool errors instead of
silently matching everything (intended). New tests: phase4 `query_rejects_unknown_operators_loudly`,
napi JS rejection test. All call sites adapted (lib tests, phase4/6, benches, napi tasks,
server). 271 Rust + 73 napi green.

### G5 — phrase `Exclude` over-excludes (full-text search)
[src/search.rs](src/search.rs#L481): excludes diff against token-conjunction candidates,
not verified phrases. Fix: verify phrase excludes against raw text before diffing.
**FIXED 2026-09-28:** exclude candidates are verified against the raw field text BEFORE
the candidate diff — covers both supersets: phrase excludes (conjunction ≠ contiguous
phrase; docs with scattered tokens survive) and case-sensitive term/prefix excludes
(case-insensitive index matches ≠ exact-case occurrence). `verify`'s per-query logic
extracted into `matches_raw` (shared); the exclude clause dropped from `needs_verify`
(the diff is the verification). Regression tests `phrase_exclude_only_excludes_contiguous_phrases`
+ `case_sensitive_exclude_only_excludes_exact_case`, both verified to FAIL with the
retain disabled. 273 Rust + 73 napi green.

### G6 — item `verify` can panic on a hand-corrupted journal
[src/item.rs](src/item.rs#L428): `expect("live item has facts")` — but `from_json` accepts
`state:"live"` with no facts. Fix: enforce live-requires-facts in `from_json`
(Corruption), no `expect` in verify.
**FIXED 2026-09-28:** `from_json` enforces the full live-record contract at the journal
boundary — facts present AND passing `validate_facts` (the same validator `commit` uses),
so a hand-corrupted `items.jsonl` fails `open()` with a Corruption naming the line.
`verify`'s field accesses converted to anomaly reports — a diagnostic must report the
corruption it exists to find, never crash on it. Test: live-without-facts and
invalid-facts journals both fail open loudly; reserved-without-facts still opens.
274 Rust + 73 napi green.

## Decisions (David, 2026-09-28)

- **D1 (was R2, set/remove/array_push on unresolvable paths):** do NOT make it an error
  (schemaless design — there is no invalid path, David's own objection). Instead **report
  honestly**: ops return whether anything actually changed (`applied: true/false`, the shape
  `ndb serve` already computes). Behavior unchanged; the "ok" lie dies.
- **D2 (was R4, journal corruption):** **auto-heal the tail, refuse the middle, always report
  loudly.** A bad last line (crash mid-write) is trimmed at open with a loud report
  ("history cut at line N") — no downtime. A bad line with valid lines *after* it means
  unknown damage → open refuses, `ndb recover` by hand. Same policy for both journals
  (data.jsonl becomes strict like items.jsonl, plus the tail-heal).
- **D1 — IMPLEMENTED 2026-09-28** (walkers return an applied bool; `set`/`remove`/`array_push`
  → `Result<bool>`; `Ok(false)` early-returns before the journal — no-op ops write nothing;
  napi forwards the flag; serve PATCH uses it instead of the before/after diff; B2's unwraps
  in `handle_patch` removed in the same hunk. 259 Rust + 72 napi tests green.)
- **D3 (was R1, `Persistence::Scheduled` is a silent no-op):** OPEN — A: implement the timed
  flush; B: remove the option (throws "not implemented"). Recommendation: B.
  It never worked, nobody can rely on it.
